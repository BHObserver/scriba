In every run the sales lines are `unknown` (the page doesn't say নগদ or বাকি; U2 asks). That costs every run 5 to 7 type fields against the draft truth's `cash_sale`, the same for both methods. Every run reads V02's "চিনি ১৬০ + চাল ১৪০ — ২৭০" as one line.

**What this shows:**
- **The errors aren't about resolution.** The crops I looked at are sharp (V01's two, V02's sales, visit and scribble crops): V02's visit crop shows ১০০০, আটা ১ and তেল ১ cleanly, and two-pass still misread them. On a flattened page the model misreads this writer's digit shapes (১/৯, ৭/৯, ৬/৩), and 2.3× more pixels per character doesn't change that. C2's flattening gave the resolution gain.
- **Out of context, a block loses the writer's hand.** On the whole page the same ১ appears a dozen times. A crop holds a few, so it has fewer examples of how this writer forms each digit (a guess at the cause; it fits ১০০০ → ২০০০ and ১ → ৯ in a clean crop).
- **A small struck-out mark becomes a block.** Pass 1 boxed V02's crossed-out scribble as an `other` block both times. Read alone, it became an amount (marked struck out and flagged, so it would show as noise, not count).
- **The one gain is the block kind:** two-pass called the sales block `day_sales` in 4 of 4 runs, single pass in 1 of 4 (`other` otherwise). That matters to U2's "were these cash sales?" question. It can be won more cheaply in prompt 6 (F2, below).
- **Cost and time:** 2.5× the cost, 1.8× the wait.

**Decision:** keep `SCRIBA_TWO_PASS` off, in Vercel too. Keep the code: it's tested, off costs nothing, and it may help on pages it wasn't measured on (dense pages, many blocks, the khata's small boxes). If F2 brings such pages, measure there before switching it on.

**Scorer:** lines are now paired by content (`src/lib/evaluation/align.ts`): an order-keeping alignment that pairs the lines with the most in common (amount, item, party, quantity, unit, type). A merged line now costs only its own lines; strict order alignment had scored V02 at 48.9% of fields because one merged line shifted everything after it. `--align=order` gives the strict score, which the app's evaluations still use (`evaluateSample` takes optional pairs; stored evaluations are unchanged).

## Part 1: what's built

- **Credit rules first** (`tests/credit-control.test.ts`, 13 new tests): a run is 1 + N calls, N ≤ 6; usage and cost are the sum; every call is kept; a failed block call fails the run and nothing is retried; a failed or unusable layout stops before any crop; a crop failure records the layout call; no cropper means nothing is sent; the cache never mixes two-pass and single pass; the switch only applies to prompt 6. `two-pass.ts` may import the transport for types only.
- **Rate limits count model calls**: `countPaidRunsSince` became `countModelCallsSince`, and a run starts only if all the calls it may make still fit (`lastHour + 7 > limit` refuses a two-pass run). A single-pass run still counts 1, so nothing changes with the switch off.
- **Pass 1** (`LAYOUT_PROFILE`, schema `scriba-layout-1`): page fields and blocks with boxes, no lines. Its prompt carries prompt 6's block rules word for word, plus "make the box larger rather than smaller".
- **Pass 2** (`BLOCK_PROFILE`, schema 3): prompt 6's rules word for word after a short "this image is one block" preamble. The user text is the first look as a hint (`blockUserText`: kind, heading, party, person).
- **`src/lib/extraction/two-pass.ts`**: `planCuts` (pads each box by 8% of its size, at least 25 grid units), `readTwoPass` (layout, then all crops in parallel), `mergeBlockReadings` (crop boxes mapped back to the page grid by the rect actually cut, ids renumbered across blocks, doubts follow their line, the crop's reading wins over the first look field by field, the worst legibility wins), `callsOfRun`.
- **Fallback**: no blocks, a block without a usable box, or more than 6 blocks: the page is read whole in one more call (2 in all), with a warning saying why.
- **Cropper** `cropBlocksForReading` (`src/lib/images/crop.ts`): decodes once (EXIF applied), cuts whole pixels, upscales toward 3.3 MP but at most 3× per side, JPEG q92 4:4:4.
- **Pipeline**: the two-pass branch sits beside the single call; the tail (checks, save) is shared. A run records `scriba-prompt-6+2pass-1`. With the switch on, each call times out at 140 s so two steps fit the route's 300 s.
- **`live:extract --two-pass`** (needs `SCRIBA_PROMPT_VERSION=scriba-prompt-6`) saves every call and writes the crops to `private-test-data/crops/`. **`scripts/score-readings.ts`** scores saved readings offline: fields, amounts, missing lines, block kinds and grouping (`src/lib/evaluation/blocks.ts`), cost and time.

## Decisions

- **No migration.** The run row holds the sums (tokens, cost; elapsed = layout + slowest block). `raw_output_text` holds every call as JSON (`scriba-two-pass-1`: pass, block, usage, cost, ms, output or error). `result.reading` holds `{ passes, calls, fallback, crops }`.
- **Counting without a column:** a succeeded two-pass run counts its `result.reading.calls`; a pending or failed one counts 7 (the most it may have made). Safe, at times strict.
- **Any failed call fails the run.** A reading missing a block would look complete. If any call may have been billed, the run is `uncertain`.
- **Block calls run in parallel** (≤ 6). If Meta rate-limits that, cap the concurrency (measure first).
- **A line from the padding** (its centre outside its own block and inside another block) is left out with a warning; the other block's own crop has it. A crop that plainly holds two blocks keeps both (the second is added after the layout's blocks).

## Offline evidence

- Using U1's single-pass block boxes for V01 and V02 as a stand-in for pass 1, every line fell inside its padded cut (22/22). The crops reach the model at about 1.5× native size; the whole page reaches it at about 0.63×. That is about 2.3× more resolution per character. The V01 Pran crop is clean: the heading, 5 lines, "পরে হিসাব নেব", and a sliver of the sales block at the top edge.

V02 prompt 6: 10 of 12 lines, fields 48.9%. The model merged "চিনি + চাল" into one line, which shifts the strict line-by-line alignment.
