## What's done

- **Engine** (`src/lib/questions/engine.ts`, pure): `buildQuestions({ page, rows, doubts, parties, capturedOn })` → `{ questions, later }`. Order: block by block down the page (what the block is, then line by line, then its sums), the date last. Kinds:
  - `meaning`: visit or account blocks ("Selim came from Praan… Right?") and `other` blocks. Day sales and expenses are not asked.
  - `same_party`: a new name close to a party already in the book, across scripts (`similar.ts`: Praan = প্রাণ, Fresh = ফ্রেশ, Karim = করিম; রহিম ≠ করিম). Yes writes the book's name onto the block or the lines.
  - `block_kind`: two or more day-sales lines with no kind → "were these all cash?" (all on credit only when every line has a name), or line by line. Same for expenses.
  - `direction`: a line with no kind, one the model was unsure of (its doubt options first), or one that points the wrong way for its block. Up to 4 kinds that fit where it's written.
  - `doubt`: model readings to choose from (no proposal), one unsure reading ("I read ৳140. Right?"), or a number that doesn't parse (typed only).
  - `price` per goods line; `delivery` when a company left ≥ 2 unpriced goods (see Decisions).
  - `opening`: an account with no "due before" (adds the line, or "0" for "nothing").
  - `unbalanced`: balance, running balance, written total or qty × rate fails. Options: "use ৳X" (code's figure), "keep" (accepts the problem), "show me" (local).
  - `date`: no date written. The photo's day is proposed, or the day before, or a typed date `parseWrittenDate` reads.
- Each question has `id`, `fp` (fingerprint of its subject), `block`, `entry`, `field`, `entries` (for strips), `sentence` (i18n key and args), `options` (each with its `changes`), `proposed` (the one-tap option or null) and `input` (`money | quantity | text | date`, or null).
- **Answers** (`answer.ts`): `answerQuestion(input, id, fp, answer, now)` refuses stale fingerprints, unknown options, local options and invalid values. `applyChanges` is the pure preview. `acceptedFindings(page)` returns the fingerprints accepted by "keep".
- **Routes**: `GET /api/runs/[id]/questions`. `POST /api/runs/[id]/answers` takes `{ question, fingerprint, answer: { option } | { value } }` and returns `{ page, rows, questions, later }`. Errors: 409 `stale` (reload), 422 `bad_value`, 400 otherwise. Writes go through `entry_reviews` and `page_reviews` with version checks, so they're audited by the existing triggers. Nothing is confirmed.
- **Voice**: `src/lib/voice/answer-words.ts` (`readYesNo`: হ্যাঁ, জি, ঠিক আছে / না, ভুল, ঠিক না; "জানি না" and "না, ঠিক আছে" are null). `/api/voice` also returns `yesNo`. `speech.ts` `spokenAnswer(question, transcript)` proposes an option or value, never saves. Numbers go through P1's parser.
- **Text**: `q.*` keys in `bn.ts` and `en.ts` (a Track A file; only a new section was added). `text.ts` `sentenceText(i18n, sentence)` renders, with money and digits in the locale.
- Small shared changes: `PageValues.answers` and `answerRecordSchema`, `keepAnswers` in the page route, `lineOrderAfter` (`src/lib/review/line-order.ts`, also used by the add-line route), `live:voice` prints yes/no.

## Decisions (reasons in IMPLEMENTATION_PLAN)

- **No migration; answers live in `page_values.answers`**, the latest per question. An answer hides its question only while the fingerprint matches, so a value that changes is asked about again. The record stores the fingerprint *after* the answer, so choosing "customer's account" doesn't bring back "this is X's account, right?". `meaning` fingerprints the kind only, so a same-party rename doesn't reopen it. Writes are not one transaction; a half-saved answer is re-asked.
- **Delivery total**: adds one line (items and source texts joined) and rejects the unpriced lines. Approval rules unchanged.
- Questions are also produced for prompt 4 readings (no blocks: one page group). B7 may keep the old cards there.
