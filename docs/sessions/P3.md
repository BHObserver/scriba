## What's done

- **Engine (`src/lib/learning/profile.ts`, pure):**
  - It compares what the model read (`extracted_entries`, never edited) with what he confirmed (`confirmed_records`).
  - `digitSwaps` counts a misread digit only when the read and confirmed numbers have the same digit count and most digits agree. It compares by value, so `180` against `১৮০` is no misread.
  - The profile holds the confusions (count, then most recent), the corrected numbers on the last 20 pages, and `learnedFrom`.
  - It also picks up to 4 reference lines. Misread lines come first, then lines holding a "hard" digit. It takes one per page where it can, newest first, and only lines with a photo.
  - `personalHints` keeps confusions seen at least twice (5 at most) plus the references, and makes a key from them.
- **Prompt 5** (`scriba-prompt-5`) is prompt 4 plus three fixed writer rules: references are never entries, numbers are never copied from them, and the page is the last image. Schema 2 is unchanged.
  - The writer's notes go in the user message. The order is notes → reference JPEG → "Now transcribe…" → page.
  - Only prompt 4 can carry the notes. With `SCRIBA_PROMPT_VERSION=scriba-prompt-3` the personalizer isn't even asked.
- **Pipeline:** the optional `personalize(doc)` is built from every page except the one being read, so a page never learns from itself.
  - The reference image is cut **before** the cache key, and the key includes `personalKey`. A personal reading never shares a cache entry with a plain one, and older keys are unchanged.
  - The run records `prompt_version = scriba-prompt-5`. If the notes fail to build, it falls back to a plain prompt 4 reading.
- **Server:**
  - `learning-data.ts` holds the samples (one embedded select, the latest 1,000 lines), the switch, the personalizer and the panel data.
  - `line-crops.ts` is `cutConfirmedLines`, moved out of `/api/crops`, which now uses it.
  - `GET/PUT /api/learning` reads the panel and sets `{ on }`. `runAnalyze` adds the personalizer only when his switch is on.
- **UI** (a Track A change, kept to new files plus small hooks):
  - The learning card in More links to `/settings/learning`, the D4 `learn` screen.
  - The panel has the mix-up rows, the latest example's strip (`/api/crops`), and the reference strip, which is exactly the image the model is shown. Then the switch, then `learn.honest`.
  - New string `learn.mixRow1` ("once"; "1 times" read badly). CSS is in `src/components/more/learning.css`.
- **Demo:** `DemoPage.readAs` holds a few misread amounts (৮→৪ ×4, ৬→৩ ×2, ১→৯ ×1), one every 4 cash pages, newest first. The seed stores the misread as the reading and his value as the confirmed one. A test checks that each misread fails a code check.

## Decisions

- **The switch lives in auth `user_metadata.scriba_learning`, not in a table.** It's his own preference about his own readings, and that avoids a migration on the dev and production projects. `SCRIBA_LEARNING=off` is the deployment's kill switch.
- **References are described from confirmed fields, never `source_text`.** He may correct the amount without fixing the free text, which can still hold the misread.
- **What goes to Meta** is described in SECURITY_AND_PRIVACY.
- **No accuracy promise anywhere.** The copy says the aim is fewer misreads, and every line is still checked and approved.
