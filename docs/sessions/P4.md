## What's done

- **Printed page:** `scripts/khata/page.html` is the D4 design ported (seven columns, the carry and total rows, faint "বা জ"). `scripts/khata-pdf.ts` prints it through Edge. It stops if the fonts didn't load or if a PDF isn't exactly one page.
- **Prompt:** `withLayout(profile, "scriba_khata")` appends `KHATA_LAYOUT` to prompt 4 or 5. The version becomes `scriba-prompt-4+khata-1` or `scriba-prompt-5+khata-1`, so the run row, the cache key and `result.promptVersion` all record it. With another base prompt (`SCRIBA_PROMPT_VERSION=scriba-prompt-3`) the page is read as written. Schema 2 is unchanged.
  - The layout block covers: what is print, never text (corner squares, title, দোকান, পাতা নং, headings, row labels, tips, the faint বা জ); the column order; "the column decides the field"; a circled বা/জ feeding the existing বাকি/জমা rules; carry row → `opening_balance`, total row → `closing_balance`; one entry per row; and `date_text` from the first তারিখ.
  - If the photo shows no printed page, the model is told to ignore the section, so a wrong tick costs little.
- **Pipeline:** `AnalyzeRequest.layout` is optional. When it's absent ("check again", the details page), the page keeps the layout of its latest run of any status (`repo.latestPromptVersion`). A failed khata reading retried from /check is therefore still a khata reading.
- **Also fixed:** the stored `result.promptVersion` now records the version actually sent. It used to say prompt 4 for prompt 5 runs.
- **API:** `POST /api/documents/[id]/analyze` accepts `layout: "free" | "scriba_khata"`.
- **UI** (Track A files, kept small):
  - The capture switch is remembered on the phone (`khata-pref.ts`, localStorage, with a memory fallback). It applies to every page in the send.
  - The print card in More.
  - New strings `cap.khata`, `cap.khata.tip`, `more.print.a5`, `.a5.b`, `.a4`, `.a4.b` and `.how` (bn and en; not in COPY.md).

## Decisions

- **No migration.** The layout lives in the run's prompt version, not in a `ledger_documents` column. That means no hosted DB change on dev or production, and evaluation can still split runs by version.
- **Static PDFs, committed.** Bangla needs real text shaping, which a PDF library on Vercel can't do, so Chromium prints them once. Regenerate after any change to `page.html`.
- **An A4 two-up PDF as well as the A5 one.** A5 paper is uncommon in a local print shop, and A4 cut in half gives two pages.
- **Corner markers moved from 3 mm to 5 mm**, with the header and footer text inset to clear them. Many printers can't print the outer 3–5 mm.
- **Total row = `closing_balance`.** The existing balance equation then checks customer-credit pages, and the continuity check can link pages. On a mixed page it is shown honestly as unverifiable. A total written as a plain sum of sales therefore isn't checked as a subtotal; F2 can revisit this with real pages.
