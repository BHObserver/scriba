# U1: blocks (2 Nov 2026)

**Status:** done. `bun run check` passes (633 tests, 22 new) and so does `bun run build`. Live spend **$0.448** (6 calls, logged below). **No hosted-DB change.** Prompt 4 stays the default; prompt 6 runs with `SCRIBA_PROMPT_VERSION=scriba-prompt-6`.

## What's done

- **Schema 3** (`src/lib/extraction/schema.ts`): `page` (no `account_name`), `blocks[]`, `entries[].block`, `doubts[]`. A test keeps the JSON Schema and zod in agreement and strict-mode clean. Doubts can't be about `text`.
- **Prompt 6** (`prompt.ts`): blocks grouped by meaning, a heading applies to the lines beside or below it, words copied in their own script (digits still follow prompt 4's rules, which are sliced from prompt 4 so they stay word for word), role words, goods with no price, doubts. Company names in both scripts, and "goods by the carton or sack with no price are a delivery". The khata layout and prompt 5 stay on prompt 4.
- **Parser** (`parse.ts`): picks the schema from the profile. Blocks: ids de-duplicated, "Praan (Selim)" split into party and person, and an account block without a party takes its heading. A line naming no known block goes to one `other` block, with a warning. Doubts: only valid values for the field, the entry's own reading first, at most three, deduplicated by value, field added to `review`. `pageValuesOf()` gives the page values with blocks.
- **Blocks helpers** (`src/lib/ledger/blocks.ts`): party kind of a block kind, `groupByBlock`, `isUnpricedGoods`, `splitPartyPerson`.
- **Parties**: on a block page the block decides (`blockPartyLink`). Visit and account blocks link to the block's party, including balance lines; day sales link each line to its own customer. A line typed against its block (a repayment in a visit) gets no party.
- **Checks** (`scriba-validator-3`): written totals, the balance equation and running balances run **per block**. Supplier sign: + `credit_purchase`, − `supplier_payment`. Unpriced goods make the balance `unverifiable` with `reason: "unpriced_goods"` and the known part in the message ("৳1,300 so far"). Findings carry `block` and `reason` (code only, not stored). Pages without blocks behave exactly as before; their finding keys are unchanged, so earlier acknowledgements still match.
- **Review**: `entryValuesSchema.block`, `pageValuesSchema.blocks`. The line-edit and page-edit routes keep stored blocks when a client sends values without them.
- **Tests** (`src/lib/extraction/blocks.test.ts`): the Pran page with the day's sales beside it, from model output through parse, checks, parties and approval. Pran ends as supplier "Praan" owed ৳1,300 + goods, unverifiable; priced goods then balance against a written due.
- `scripts/fetch-v3-samples.ts` downloads the two 1 Nov photos (read-only) to `private-test-data/v3/V01.jpg`, `V02.jpg`.

## Decisions

- **Storage: JSON, no migration.** Reasons are in IMPLEMENTATION_PLAN ("Blocks storage"). The rep isn't on `confirmed_records`; add `person` there in one additive migration if the party ledger needs it.
- **Goods are priced per line.** They can't be confirmed without an amount (the existing rule). A block delivery total is U2's to design.
- **Prompt 6 is not the default yet.** The old check screen can't show blocks, and goods lines would sit there unapprovable. B7 flips the default.
