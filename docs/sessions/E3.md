# E3: server data, crops, demo shop (1 Nov 2026)

**Status:** done. `bun run check` (372 tests, 14 new) and `bun run build` pass. No Meta calls, $0 spent. The demo shop is seeded in the **development** project (`faozgszucjoqcehrewab`) with the user's go-ahead, including S01/S04.

## What's done

- **Loaders** (`src/lib/server/shop-data.ts`, server-only, user client and RLS):
  - `loadShop` reads everything once: profile, pages, records, parties, closes, readings and drafts. It pages past PostgREST's 1,000-row cap.
  - Each screen takes the result: `todayData`, `closeData`, `duesData`, `partyData`, `historyData` and `searchData`.
  - `lineDetails(ids)` is for drill-downs, timelines and search results. Each line comes with a strip (signed URL, size, turns, box), or `strip: null` with `samplePage`.
- **Writes:**
  - `saveDayClose` recomputes the day on the server (ignoring that day's own earlier close) and upserts the snapshot through the service client.
  - `mergeParty` and `unmergeParty`.
  - `saveShopProfile` updates the profile, or inserts one when none exists. It never upserts, because `owner_id` has no update grant.
- **Pure, tested** (`src/lib/shop/`):
  - `rows.ts`: row → engine mapping, `pageInfos` (unread / waiting / checked) and `dayPages`.
  - `history.ts`: `historyDays`, `searchLines` (names through the party key, so spelling variants and merged parties match) and `mergeProblem`.
  - `demo.ts`: the demo shop generator and `closeSnapshots`.
- **Routes:**
  - `POST /api/close {date, countedCashPoisha, note}`.
  - `/api/lines`: `POST {ids}` returns line details; `GET ?q=` searches History.
  - `PATCH /api/parties/[id] {displayName}`.
  - `POST` and `DELETE /api/parties/[id]/merge {into}`.
  - `GET` and `PUT /api/shop`.
  - `GET /api/crops?records=…` takes up to 8 lines and returns one stacked JPEG, with `private, max-age=600`.
- **Crops** (`src/lib/images/crop.ts`):
  - The photo is first turned upright: EXIF orientation, then the turns of the record's own reading, because the model's boxes refer to that frame. The crop is padded, scaled to 900 px wide, stacked on paper colour and saved as a fresh JPEG without metadata.
- **Confirm guard (E2 item 2):** the confirm route returns 409 `page_already_confirmed` when another reading of the same page already has confirmed lines.
  - Record building moved to `src/lib/review/confirm-record.ts`, shared with the seed.
- **Demo shop** (`bun run seed:demo [--yes] [--photos]`): a dry run unless `--yes` is given.
  - **Account safety:**
    - It refuses to touch a user without `user_metadata.scriba_demo`.
    - It deletes and recreates the demo user, so the wipe is complete.
    - It writes `SCRIBA_DEMO_EMAIL` and `SCRIBA_DEMO_PASSWORD` to `.env.local` (copied to `../scriba/.env.local` too).
  - **Contents:**
    - D3's মায়ের দোয়া স্টোর grown to 60 days: 81 sample pages, 476 lines, 15 parties and 5 closes (one ৳৫০ short, one ৳২০ over).
    - Every line goes through `scriba_complete_extraction` and `scriba_confirm_entries`, like the app.
    - **Verified through RLS as the demo user:** drawer ৳৪,৩২০ from the usual ৳১,৫০০, sales ৳৬,২৯০ (৳১,৩৪০ credit), three flagged dues and a busy Friday.
  - **`--photos`:** S01 and S04 are today's pages 4–5, unchecked, with E1's stored prompt-4 readings. Scriba's note says "pages 4, 5 waiting, 12 lines". The deck can be demoed on real handwriting at no cost.

## Decisions

- **No migration.** Merges and closes use the service client after the route verifies the user; renames and the profile go through RLS.
- **A merge only sets `merged_into`.** Records keep their party, the engine follows the merge, and it can be undone.
- **Sample pages have no photo.** They are marked `dataset_label = 'demo-sample'` (`hasPhoto()`) and never show fake handwriting. Only real readings of real photos get strips.
- **Closing a day again replaces the earlier close**, so a day whose lines changed after closing can be closed again.
- **Screens read on the server.** Screens are server components that call the loaders. Routes exist only for client actions: drill-down fetches, search, close, merge, profile and crops.
