# C1: full-resolution still photo (2 Nov 2026)

**Status:** done. `bun run check` passes (611 tests, 8 new) and so does `bun run build`. **No live calls.** This session also wrote `docs/PLAN_V3.md`, the plan for scan and understand, from the user's first real-page test, and added a pointer to it at the top of MASTER_PLAN.

## What we learned first

- The user's two test photos (demo account, 1 Nov 18:36 UTC) came from Scriba's own camera at **2160×3840**, which is 4K portrait video. I read only the metadata (size, filename, time); the photos weren't opened.
- So the problem with distant shots isn't a low-resolution camera. The page is a small part of a 9:16 frame, and Meta shrinks the whole frame to about 3.3 MP. **C2 (find and crop the page) is the main fix.** C1 helps on top: a real still is sharper, focused for a still, and 3:4, so a page fills more of it.

## What's done

- **`src/components/capture/still-photo.ts`.** `takeShot(video, track, { maxBytes, quality })`:
  1. Draws the preview frame at the moment of the press.
  2. Tries `ImageCapture.takePhoto()`.
  3. Uses the still only if it's the same way up as the preview, with EXIF orientation applied through `createImageBitmap`. Otherwise it falls back to the frame.
  4. Keeps the camera's own JPEG when it fits: JPEG type, ≤ the upload limit, ≤ 12 MP.
  5. Otherwise re-encodes it at ≤ 12 MP. If it's still over the upload limit, it shrinks by 0.8 per side, up to 3 tries, then falls back to the frame.
  6. A still that fails or takes more than 5 s also falls back to the frame.
- **Shutter** (`capture-screen.tsx`): it uses `takeShot`, takes one press at a time (`shooting` state, `aria-busy`), and the flash still fires on the press.
- **Tests** (`still-photo.test.ts`): orientation matching, scaling to the pixel cap, and the keep-or-re-encode decision.

## Verified

Edge with a fake camera (`--use-fake-device-for-media-stream`), signed in as the demo shop at 390×844, pressing the shutter on /capture. No console errors in any case.

| Case | Result |
|---|---|
| Edge's real ImageCapture | Still used (PNG from the fake camera, re-encoded as a 3840×2160 JPEG) |
| No ImageCapture (Safari) | Frame |
| Still fails | Frame |
| Still never returns | Frame after the 5 s limit |
| Still portrait, preview landscape | Frame |
| PNG still 1600×1200 | JPEG 1600×1200 |
| JPEG still that fits | Kept byte for byte |
| 48 MP still | 4000×3000 |

**Not verified:** a real Android phone. The fake camera's still takes about 4 s in headless Edge; a phone should take 0.5–2 s. The tray has no busy indicator beyond the disabled shutter. F2 should check the shutter delay and whether phones return the still upright.

## Decisions

- **Fall back rather than rotate** when the still's orientation doesn't match the preview. Guessing the turn direction could hand him a sideways page; the frame always matches what he framed.
- **12 MP cap.** After C2 crops the page, that still leaves more page pixels than the model's 3.3 MP. 50 MP phone stills would otherwise break the 8 MB upload limit.
