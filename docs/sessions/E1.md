## What's done (worktree `../scriba-engine`, branch `track-engine`)

- **Migration** `supabase/migrations/20261031120000_scriba_shop_v2.sql`, additive only:
  - Money-out types in both type checks.
  - `ledger_documents.business_date` and `business_date_source`, backfilled from `uploaded_at` in Dhaka time.
  - `parties`, `confirmed_records.party_id`, `shop_profiles`, `day_closes`.
  - `scriba_confirm_entries` replaced with the same signature; it now upserts parties and links records.
  - RLS and grants. The six new tests in `tests/db/rls.test.ts` cover isolation, who may write what, merges and the type checks.
- **Types:** `TRANSACTION_TYPES` gains `purchase`, `credit_purchase`, `supplier_payment` and `expense`, plus `MONEY_OUT_TYPES` and English labels.
- **Checks** (`scriba-validator-2`):
  - A written subtotal adds the run of one family directly above it: sales, or money out. It never mixes the two.
  - qty × rate was already type-independent.
  - The balance rule is unchanged: a money-out line on a customer page makes the balance unverifiable.
- **`src/lib/ledger/parties.ts`** finds each line's party from its type:
  - The normalized key folds ী/ি, ূ/ু, শ/ষ/স, ণ/ন and ৎ, strips the মোঃ/মোহাম্মদ prefix, and strips titles (ভাই, সাহেব, দা, মহাজন…) only when a name remains.
  - `partyLinkFor` sets the kind by transaction type. Balance lines take the page's side.
  - The name falls back to the page's account name on account pages.
  - Expenses, totals and unnamed cash sales get no party.
- **`src/lib/ledger/dates.ts`** turns the written date or the capture day into the business date:
  - Accepts ৩১/১০/২৬, ৩১.১০, ৩১ অক্টো, অক্টোবর ২৯, ২৯শে অক্টোবর, 31 Oct 2026 and তারিখ: … ইং.
  - Converts Bangla calendar dates (১৪ কার্তিক [১৪৩৩]) with Bangladesh's revised calendar.
  - A missing year means the latest year that isn't in the future.
  - Dates more than 7 days after the photo, or more than 400 days before it, are ignored.
- **Confirm route:** sends `party_kind/key/name` per record. After a successful confirmation it sets the business date from the reviewed date text, but never over a `user` date. This is best effort.
- **Prompt 4** (`scriba-prompt-4`, schema `scriba-extraction-2`):
  - Teaches the new types and their cue words.
  - Says জমা/বাকি depend on who is on the other side.
  - Says `customer` holds the supplier on purchase lines.
- **Prompt 3 is still available:** `SCRIBA_PROMPT_VERSION=scriba-prompt-3` runs it byte-identical with schema 1, exactly as measured. `getExtractionProfile()` in `prompt.ts` is now the single source for transport, pipeline, parse, the evaluations route, live-extract and Settings.
- `docs/DATA_AND_SCHEMA.md` has a v2 section; `.env.example` documents `SCRIBA_PROMPT_VERSION`.

## Decisions

- **Party linking happens inside the confirmation function, so it is atomic.** The key is computed in TypeScript, where it is tested.
  - Parties are unique per (owner, kind, key).
  - A merged party keeps its key with `merged_into` set, so later spellings follow the merge.
- **Who writes what:**
  - `day_closes` are server-only, because the expected cash is computed by code.
  - Users can only rename parties. Merge belongs to E3, which must re-point `confirmed_records.party_id` through the service role or a definer function.
  - `shop_profiles` are written by their owner, except `is_sample`.
- **Business date is set at confirmation, not at extraction.**
  - Before that, the UI can compute it client-side with `businessDateFor(dateText, uploadedAt)`.
  - Timezone is fixed to Asia/Dhaka.
  - I converted Bangla calendar dates instead of leaving them as text: the conversion is deterministic and tested.
- I didn't rename the schema field `customer` to "party": that would churn every layer for no behavioural gain.

## For E2 and later

- Use `SALE_TYPES`, `MONEY_OUT_TYPES`, `confirmed_records.party_id` and `ledger_documents.business_date`.
- **Opening balances:** on customer pages they repeat the previous page's closing balance. Don't add them to receivables naively: use them only as a party's starting point when no earlier records exist.
- **Fresh worktree setup:** run `bunx next typegen` before `bun run typecheck`, which needs the `PageProps`/`RouteContext` globals. `private-test-data` is a junction to `../scriba/private-test-data`.
